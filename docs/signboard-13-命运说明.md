# signboard-13「媒资桥校验校验和后才可播」命运说明（当日拍板，写后锁死）

- 日期：2026-11-27

- 互斥名（全局唯一，逐字使用）：**媒资桥置可播互斥**（代码常量 `MEDIA_LOCK_KEY`）。

## 正确性口径：拍板走【甲路径】，且只走甲，禁止与乙混用

**甲路径定义（本仓唯一实现口径）：**

1. 媒资桥同步必须实际比对「台账/期望校验和」与「媒资中台回传校验和」，一致才允许把素材置为正式可播
   （`assets.status='ready'` 且 `checksum_status='verified'`）。
2. 校验失败（不一致 / 校验和缺失）时，**整笔拒写 ready**：同一事务内把素材正式状态压回/保持为 `draft`、
   `checksum_status='mismatch'`，正式可播计数零增；随后该素材任何置可播尝试一律 409，直至下一次校验一致。
3. 校验结果（媒资桥结果）落 `media_verifications` 跨表台账，并与 `assets` 状态、审计 `audit_log`、
   变更历史 `change_history` 在**同一个数据库事务**内提交/回滚，做到「媒资桥结果 ↔ 素材状态」同事务跨表账实一致。
4. 播放清单是否「可播齐套」不再只看 `assets.status`，而由清单服务**联查**
   「`assets.status='ready'` + `checksum_status='verified'` + 存在与当前 checksum 相符的 matched 台账」判定；
   ready 但未核/核败的素材不计齐套，清单标 `complete=false` / `fake_ready=true`。
5. 「媒资桥置可播互斥」约束双会话/双线程：进程内命名互斥（非阻塞取锁）+ SQLite `BEGIN IMMEDIATE`
   事务互斥 + `write_locks` 命名行锁（兼容 `/api/locks` 外部持锁）三重保证。争用恰一成一败，
   败方 409 且**零正式落库**（无素材状态推进、无媒资核验行、无审计/历史）。

### 为什么不是乙（明确排除，防止折中双轨）

乙路径要求「校验失败仅写媒资影子待核草案，正式册保持草稿，后续原子升正」。本仓**不建**任何可升正的
`media_shadows` 影子草案表/状态机，也不提供媒资影子升正端点。`media_verifications` 是**只增、不可升正的
核验台账（事实记录）**，不是影子草案：它不会把任何失败素材提升为正式可播。因此不存在甲乙双轨混用。
